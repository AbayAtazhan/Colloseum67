# Standalone free hackathon demo (Render)

This deployment runs the actual production site, agents, SQLite journal and a private Hardhat chain together on a remote server. The laptop can be off. It is a demo service, not mainnet or a durable production deployment.

## Publish

1. Put the project source in a **private** GitHub repository. Never upload `.env`, `data`, `node_modules`, `.next`, `cache`, `artifacts` or a chain context. `.gitignore` already excludes these. Do not upload the entire laptop folder or an archive containing credentials.
2. Sign in to Render. Create a **Blueprint** from the repository. Its `render.yaml` specifies the **Free** plan and all commands; do not switch to a paid plan or attach a paid disk.
3. Enter `DEEPSEEK_API_KEY` as the secret requested by Render. Keep it out of source code and chat. `DEMO_ACCESS_PASSWORD` is generated by Render; find it in the service's Environment settings.
4. When the deploy succeeds, open its `https://…onrender.com` address. Enter **DEMO_ACCESS_PASSWORD** on the demo login page. Retrieve it from Render → service → Environment → Show secret. Share this password only with demo participants. HTTP API clients can also use Basic authentication with username **demo**.
5. Load demo → connect MetaMask → sign permission → two settled payments / one budget refusal. Confirm the header says **Hosted demo testnet**, chain **31338**, and wallet RPC is the HTTPS site `/rpc`.
6. Confirm the report, receipts, budget test and revocation. Real DeepSeek requires a funded DeepSeek API account; hosting itself uses the Free plan.

Manual Web Service setup (if not using Blueprint): Node runtime, Free plan, Node 24.21.0, build `npm ci --include=dev && npm run contracts:compile && npm run build && npm run build:cloud`, start `node build/start-cloud.mjs`, health `/api/health`, set the key and a password of at least 16 characters.

## Architecture and limits

- Public gateway is the only listener on `0.0.0.0:$PORT`. App and unrestricted Hardhat RPC bind to loopback. Password login protects the site and all agent/payment endpoints; only the login page, health and a rate-limited read-only RPC are public. A successful login issues a signed, 12-hour HttpOnly/Secure/SameSite=Strict cookie. Cookie-authenticated writes require a matching Origin. HTTP clients can use Basic authentication. Neither access credential is forwarded to Next.js or providers.
- The wallet RPC rejects all writes, resets, debug methods and batching. The server relayer broadcasts through the private RPC. Browser signatures still authorize real test-chain transactions.
- Cloud chain **31338** is separate from laptop chain **31337**. Internal provider calls use the private app URL, so they do not require or transmit the access password.
- Hosting runs live DeepSeek if its key is supplied. It fails startup if the key/password are missing; deterministic fixtures require explicit `SWARM_TAB_FAKE_LLM=1` and stay labelled.
- Free Render sleeps after 15 idle minutes; waking takes about a minute. Restarts/sleep/redeploy lose the SQLite journal **and blockchain state**. Every boot uses a new matched chain/journal; in-flight missions are interrupted. Old receipts do not become receipts on the new chain.
- All signed missions and funded accounts are test-only. Do not send real assets to demo addresses. The demo uses well-known Hardhat accounts and is not a public financial service.
- Free plan resources are limited (512 MB RAM); actual Linux cloud memory and uptime must be verified after deployment. No automatic paid upgrades are configured.
- Persistent accounts/history and public testnet payments require a different backend/storage setup and funded Base Sepolia gas accounts. Vercel alone cannot preserve the current in-process runner, local chain and SQLite writes.

Official hosting limitations: https://render.com/docs/free

## Local production verification

First build and compile, including `npm run build:cloud`. To try the cloud entry point on the laptop without changing its existing dev stack, build Next with `SWARM_TAB_DIST_DIR=.next-cloud`. Set that same variable, `PORT=10000`, `SWARM_TAB_INTERNAL_PORT=3001`, `SWARM_TAB_HOSTED_URL=http://127.0.0.1:10000`, `DEMO_ACCESS_PASSWORD` (16+ characters), and the DeepSeek key in the process environment, then run `node build/start-cloud.mjs`. It starts its own chain on a different port. Use explicit fixture mode to check hosting without spending API credit.

Cloud startup intentionally does not read `.env` files. Render provides the public URL automatically through `RENDER_EXTERNAL_URL`.
